# 首版验收记录

验证环境：2026-10-02，macOS x86_64；Codex CLI `0.158.0-alpha.2.1`，Claude Code `2.1.126`。测试仅使用 Node/npm、Electron 自带 Chromium 和 macOS 图形会话，未依赖完整 Xcode。

| 开发计划场景 | 验证证据 |
| --- | --- |
| A1 首次启动与重启 | Playwright 创建管理员，退出应用后用同一用户数据目录重新启动并登录；账户与数据均保留。单元测试覆盖重复首次设置和登录失败限速。 |
| A2 用户权限 | 打包版 Playwright 验证普通用户只看到已归属的记录，管理、遥测密钥和备份 IPC 均拒绝访问。 |
| A3 Codex 采集 | 从本机只读复制的 2 段真实多模型会话中，独立计算 4,713 条事实；逐条摘要涵盖时间、模型、输入、输出、缓存、总量，与采集器入库结果完全一致。 |
| A4 Claude Code 采集 | 从本机只读复制的 2 段真实多模型且包含子代理的会话中，独立计算 40 条事实；同样的逐条摘要与采集器完全一致。 |
| A5 幂等恢复 | 固定样本验证重复扫描、未写完末行、文件截断重写与轮转到新路径；遥测测试验证累计和 delta 指标重复发送不增加总量；打包版 Playwright 验证重启后重复扫描总量不变。 |
| A6 异常数据 | 固定样本和打包版 Playwright 验证目录缺失、空目录、无效 Token 字段和不可读文件的状态；解析错误在后续扫描中持续显示，避免以 0 表示已知格式错误。 |
| A7 来源归属 | Playwright 将 Codex 来源绑定到普通用户，报表立即只显示其授权用量。 |
| A8 统计 | 单元测试验证日、ISO 跨年周、月、年、时区边界及明细合计；打包版测试验证趋势柱与模型行可定位分页明细。 |
| A9 导出 | Playwright 在当前筛选下导出 CSV 并核对 12、14 Token 两行与页面 26 Token 总量一致；导出只含用量字段。 |
| A10 打包 | 项目根目录的 `Token-0.1.0.dmg` 通过 `hdiutil verify`；从 DMG 挂载并复制出的 `Token.app` 可由 Playwright 启动并完成主流程。 |

真实会话快照及临时数据库在核对后已删除。仓库仅保留人工构造的无正文测试样本。上述真实样本验证只证明当前本机可观察格式，不能推断所有工具版本、客户端入口或云端账单的完整覆盖率。

本机开发版 DMG 未签名。若面向其他 Mac 外部分发，需另行完成 Apple 签名、公证和对应设备验收。

### 0.2.0 包与跨版本登录验证

版本提交 `96e99be` 将应用版本升至 `0.2.0`，生成项目根目录的 `Token-0.2.0.dmg`。开发会话报告该提交的 `npm run test:gate`、打包应用 7/7 Electron 测试及 `hdiutil verify Token-0.2.0.dmg` 均通过；还用**同一临时用户数据目录**先在 0.1.0 打包应用信任登录，再以 0.2.0 打包应用自动恢复登录成功。这个流程验证了打包应用之间的受信登录数据兼容性，**没有执行真实安装器替换、对外发布、签名公证或另一台 Mac 安装**。TC-027/028 仍按各自人工证据单独判定。
