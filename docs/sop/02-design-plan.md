# SOP-002 设计与实施计划

入口：[SOP-001](01-requirements.md) 的需求与验收已定义。仅作技术研究时可先只读验证可行性，形成结论后再决定是否排期。

## 执行步骤

1. **分析影响**：沿 `采集器 → 标准化/去重 → 数据库 → 主进程权限与 IPC → 报表/CSV → 界面` 定位改动；标出受影响文件、数据迁移、旧数据重算和向后兼容要求。
2. **写清规则**：在[设计](../design.md)相应章节维护输入、输出、不变量和异常状态。采集改动须区分 Codex 与 Claude Code 的 Token 分类、来源重叠和幂等键；报表改动须定义 UTC 存储、IANA 时区与 ISO 周边界。未知格式、权限不足、缺失数据需保留可见状态。
3. **评估安全与数据**：确认最小文件权限、来源显式归属、主进程授权、预加载 API 范围、CSV 公式注入防护和日志脱敏。检查是否会读取或持久化会话正文、凭证、遥测密钥；发现越界方案应重设计。
4. **选择方案**：比较必要的实现路径和失败/回退方式；对不可逆迁移、来源优先级或用户数据兼容性作明确决定。重要决策写进设计文档或关联开发任务，避免只留在聊天记录。
5. **排实施和验证顺序**：把 `DEV` 分成可交付步骤；为每个 `TC` 选择单元、Electron 端到端、打包应用或目标 Mac 人工验证。先安排能推翻关键假设的最小验证，再实施依赖它的改动。

## 退出检查

- 方案能逐项满足关联 `REQ` 的验收条件；设计中的规则、权限和数据迁移边界可审查。
- 风险、回退办法、测试层级、所需环境和未覆盖项已明确；涉及发布范围的条件与 [SOP-005](05-release.md) 一致。
- 工作簿任务落点和用例预期与方案一致。通过后进入 [SOP-003](03-development.md)。
