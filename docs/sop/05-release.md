# SOP-005 构建、发布与回退

入口：[SOP-004](04-test-acceptance.md) 对拟发布范围给出可核查结论。发布对象须先区分“本机未签名开发版”和“面向其他 Mac 的外部分发版”。

## 执行步骤

1. **冻结候选**：记录提交、版本、包含的 `REQ/DEV/TC`、已知缺口和目标环境；核对本轮功能的每个受影响 `TC` 已更新、按编号单独运行并通过，且测试库已清理。任一项不满足时不交付该功能。确认工作区无混入的私有数据或无关修改。更新面向用户的覆盖说明，不能宣称未验证的工具版本、客户端入口或账单完整性。
2. **构建与核验**：运行必要类型/测试门槛，使用 `CSC_IDENTITY_AUTO_DISCOVERY=false npm run pack:dir` 构建目录并运行打包应用端到端；需要 DMG 时运行 `npm run pack:dmg`，记录制品路径、版本、架构和校验结果。制品不代替安装与启动验收。
3. **目标环境验收**：在目标 Mac 核对安装、首次启动、登录、来源检测、缺失/权限不足、采集、报表、导出和备份/恢复中与发布范围相关的流程。记录系统版本、架构、工具版本及结果；不能在目标机验证的项保持待验证。
4. **外部分发附加门槛**：若面向其他 Mac 公开分发，取得有效签名材料，完成签名、公证、票据验证及目标设备安装检查；记录证书身份、公证结果和验证命令，密钥不得入库。任何一步未完成时，只能标记为本机开发版或未完成的发布候选。
5. **交付与记录**：按已授权的发布目标交付制品，记录版本、提交、校验值、渠道、时间、验收证据、已知限制和回退办法。若新增对外承诺或验收结论，更新设计、工作簿及验收记录。确认远端提交/发布指向同一候选。

## 回退与退出检查

- 发布前保存可用的上一版本制品与数据备份位置；数据库格式变化时说明旧版能否读取新数据。出现错误计量、越权、数据损坏或无法启动时停止分发，回退制品并按已验证的备份/恢复流程处理数据，记录影响范围，再由 [SOP-006](06-maintenance.md) 跟进。
- 只有制品、目标环境和要求的签名/公证门槛都有证据时，才标记对应发布类型“完成”。本机 DMG 通过不等于外部分发完成。
