# SOP-006 运行反馈、缺陷与持续维护

入口：用户报告、采集状态变化、工具格式升级、依赖/系统升级或发布后质量问题。

## 执行步骤

1. **安全接收**：记录发生时间、应用/系统/工具版本、来源类型、可观察症状、影响范围及复现条件。只收集必要的用量元数据和人工构造复现样本；不要把真实会话 JSONL、数据库、遥测密钥或含正文日志贴入任务或仓库。
2. **定级与隔离**：优先处理越权、数据损坏、重复计量和错误归属；必要时暂停受影响来源或发布渠道，并在界面/记录中保留“未知/未覆盖”，避免继续产生误导性的零或虚高数据。记录临时措施和恢复条件。
3. **复现与根因**：核对来源格式版本、扫描游标、去重键、来源优先级、归属、时区及导出链路；把“没有数据”“数据未覆盖”“采集失败”和“真实零用量”分开。无法复现时记录已有证据与待获取条件，不猜测根因。
4. **返回生命周期**：改变用户可见行为、计量或验收条件时从 [SOP-001](01-requirements.md) 更新追溯，再执行设计、开发、测试；纯内部修复也要核对既有 `REQ/DEV/TC` 并为新回归场景分配新 `TC`，不能改写旧证据。
5. **关闭与复盘**：写明修复提交、回归结果、受影响版本/数据、是否需要重扫或重算、发布处理及剩余风险。重复问题应修订相关 SOP，并通过本目录[变更控制](README.md#本-sop-体系的变更控制)办理。

## 退出检查

- 问题有可验证的修复或明确的未解决状态；用户可见覆盖与数据风险已说明。
- 工作簿关联、测试证据、设计/验收记录和发布说明按实际影响同步；需要发布时进入 [SOP-005](05-release.md)。
