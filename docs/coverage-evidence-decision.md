## 阶段一可观察验收：受限执行、归属与结果

本阶段已交受管入口和账本的隔离自动子范围，不开放 `source-complete`、已确认零或同比正例。用户主动启用后，只有应用管理员能在明确授权的本机工作目录，以固定的 Codex/Claude CLI 和只读或计划模式启动命令。主进程和服务必须复核应用登录角色、工作目录及符号链接的真实目标、可执行文件、参数和环境白名单；不接受任意命令、写入模式或 renderer 直接指定执行路径。viewer 即使和管理员共用 macOS 用户与 CLI 凭证，也须在启动进程前被 UI 和 IPC 拒绝。

账本把 `actorUserId`（发起应用用户）与 CLI `owner` 分列。点击者、macOS UID、凭证目录以及用户自选 owner 均不能证明提供方账号归属；仅经可验证的提供方身份及有效绑定版本核对后，才能写 `owner_verified=true` 和对应 owner。缺失、错配或过期时写 `owner_verified=false`、空 owner、明确错误，并阻断该运行的报表事实和完整覆盖。服务先耐久登记 run，再启动 CLI；逐项持久记录事件、白名单计量、heartbeat、确认水位、终态与错误。解析、写库、流、服务中断或重启核对失败必须保留缺口并降级未知，不能靠下次心跳抹平。

发起管理员须在当前授权窗口看到完成/失败状态和有界结果正文，或得到明确、安全、仅当前会话可用的打开结果动作；失败应给出原因和下一步。提示词、回复及原始流正文仅短暂留在该窗口内存，关闭、登出或切换用户即清除；数据库、应用/诊断日志与反馈附件不得保存正文，viewer 不得读取。此处的“结果”不等于报表事实：owner 未证或运行不完整时仍显示覆盖未知，不把空账本说成零。

## 核对依据与结论

当前 `UsageScanner` 每 10 分钟扫描 `~/.codex/sessions`、`~/.claude/projects`，`source_status` 保存当前状态和最近扫描，`source_cursors` 保存仍存在的文件 ID、偏移与尾部哈希，`usage_facts` 保存已解析事实。目录遍历与单文件读取之间可变化；文件可在两次扫描之间生成又删除；解析失败、权限失败、超大行、未结束末行和取消均可能留下缺口。当前 `ReportService.scopedCoverage` 对有无事实都返回 `unknown`。这些表能证明“已观察”，不能证明留存起点、完整文件清单、连续运行或所有执行模式。

[Codex 官方非交互文档](https://learn.chatgpt.com/docs/non-interactive-mode)给出 `codex exec --json` 的 `turn.completed.usage` 事件；[命令文档](https://learn.chatgpt.com/docs/developer-commands?surface=cli)说明 `--ephemeral` 不持久化 rollout。[Claude Code 官方 CLI 文档](https://code.claude.com/docs/en/cli-reference)允许 `--no-session-persistence`；[程序化运行文档](https://code.claude.com/docs/en/headless)提供 `-p --output-format stream-json`，结果含用量元数据。[监测文档](https://code.claude.com/docs/en/monitoring-usage)说明遥测需显式启用，`OTEL_LOGS_EXPORTER=none` 可关闭日志，且不同桌面/云会话的设置覆盖范围不同。这些资料支持设计受管命令的捕获入口，也说明本机文件或遥测缺失不能证明工具没有运行；官方输出格式本身**不保证**本产品能取得每次请求的有效模型、项目归属或无丢弃水位，须按工具版本实测和失效处理。

## 最小可交付机制（DEV-049）

1. **显式监测范围**：产品提供由用户主动启用的“受管会话／受管来源”入口及后台采集服务。管理员选择 provider、受管执行模式和经授权的工作目录；服务先耐久写入 `run_id`、发起 actor、待验证 owner、工具版本、入口模式、项目上下文，再启动进程。仅此入口中的运行列入正向证明。普通本机全部使用量、其他 CLI、Codex App、Claude Desktop/Code tab、云会话、其他设备及未受管遥测均显式标“范围外／完整性未知”。不得把服务启动当成对这些模式的独占证明。
2. **用量与连续水位**：Codex 受管 `exec --json`、Claude 受管 `-p --output-format stream-json` 的白名单用量字段按运行 ID、事件 ID/顺序和 UTC 时间耐久写入；若上游没有可靠递增序号，由入口在读取流时分配递增序号，持久记录字节/事件确认水位，并以最终结果、退出状态和已确认的协议结束标记核对，不能凭自造序号推定上游未漏事件。保存退出码、正常终止/失败、已确认的最终用量与解析版本。后台服务记录连续存活区段、心跳、进程启动/结束、落盘/确认水位和缺口。服务退出、写入失败、流中断、事件缺序、未知格式、超限/丢弃或无法证明子代理/请求已纳入，均使相交窗口失效；重启后从持久账本核对未结束运行，不能用新心跳覆盖断点。后台服务只解析并持久保存白名单计量字段及必要元数据；不保存 CLI 参数、提示词、回复、源码或完整原始 stream，日志也不得含正文。
3. **留存起点与封窗**：用户主动启用后，首次完成持久配置、服务健康自检和启动入口接管的 UTC 时刻是最早可证起点，不回填历史。对半开窗口 `[start,end)`，只有起点不晚于 `start`、服务/账本水位连续越过 `end`、相关运行均已终结且用量已耐久确认、窗口已结束并过采集延迟界限，才封为所选来源完整；封窗必须发生在守护采集仍连续有效期间，停机后的新启动不能追认跨停机窗口。无运行的空窗也要有连续服务与启动账本证明；空心跳、当前扫描 `ready`、空扫描、最早事实、一次快照盘点或 OTel 收到/没收到数据均不足够。证明记录引用监测范围/协议版本、UTC 起止、水位、错误集合与事实集 revision；后续修复可重算但不得静默改写旧结论。
4. **授权及维度门槛**：窗口按当前授权 owner（含“未归属”）、provider、所选模式、模型、项目、IANA 时区与日期区间求证。运行归属仅由可验证的提供方账号身份和有效绑定版本证明；发起 actor、应用登录、本机 UID 或未验证 OTel 身份均不能代证。未核实 owner 的运行不进入报表事实或完整证明。每个可能产生用量的运行都须能解析当前所选模型/项目维度；若官方输出只有合计、缺有效模型或子代理/项目字段，该筛选维度的完整性保持未知，不能把“未知模型/项目”从集合中排除后宣称完整。全用户/全提供方查询须对所含每一授权范围和 provider 分别满足门槛。时区只把本地日界转换为 UTC 半开界，不改变事实时刻。
5. **失效与界面**：服务停机、机器睡眠且运行范围无法封闭、磁盘/数据库写入失败、队列溢出、权限/配置或工具版本变化、未解释的文件轮转/删除、事实/归属重绑或恢复备份后的证据版本不一致、钟表回拨、格式不识别、运行未结束使受管范围内相交窗口失效；已知的范围外运行单独登记，不抹掉受管范围自身已经成立的连续证明，但“全本机／全部模式”始终未知。界面须展示“本机所选受管执行 · 覆盖起点/截至水位 · 未纳入的模式”；固定文件另显示“仅所选文件已重放”。范围外保持未知，即便受管范围已完整，也不写服务商账单或全设备零。

完整覆盖是**上述受管范围内**的 `source-complete`，不能把 `SourceStatus=ready` 或旧事实数量映射为 `windowCoverage.complete`。窗口关闭且同一授权筛选、同一事实集为空时，REQ-044 才显示“已确认零（所选已监测来源）”，并在旁列出范围外未知。待核对事实、权限或格式错误使完整总量未知。比较要求两个半开窗口同 owner/provider/模式/模型/项目、同 IANA 时区、同证据协议及 as-of 截止口径，**实际 UTC 时长相等且双方完整**；跨夏令时导致实际时长不等时暂不可比较，直至另有明确归一化设计。今天未结束或水位滞后不可比较。

## 分期交付与前置依赖

1. **入口与持久账本**：先提供用户主动启用、管理员受限启动、actor 与经验证的 owner/provider/模式/工具版本绑定，建立运行、事件、服务心跳、错误和确认水位的耐久记录；验证异常退出后可恢复或明确作废。此期尚不输出 `complete`。
2. **覆盖判定与界面**：在授权查询中按 owner/provider/模型/项目/时区/窗口和当前证据 revision 求封窗证明；缺字段、缺口、权限变化或停机一律失效。界面展示受管范围、可证起点/截至水位、范围外未知，限定真零和比较只消费该证明。
3. **受控正例**：给 TC-077/078/084 各自独立的合成账本、单编号入口和 UI/API 断言；同时注入停机、事件丢弃、权限错误、维度未知、跨夏令时不等长，确认受管范围 fail closed；另注入范围外运行，确认受管范围证明保持、全本机仍未知。此期只证明规则。
4. **真实 CLI 正例**：锁定实际 Codex/Claude CLI 版本、测试账户和最小无正文任务，分别验证流的用量/结束语义、模型和项目维度、临时会话及失败恢复；可证明的 provider/维度/模式逐项开放正向覆盖。任一提供方不能取得必需字段或结束语义时，该来源继续未知，不因另一提供方通过而合并放行。
