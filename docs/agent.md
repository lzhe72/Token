## 不可破坏的规则

- 第一版为本机离线用量观察工具。统计口径是可观察数据，不是服务商账单或完整跨设备用量。缺失、权限不足、格式未知要显示覆盖状态，不能默认为零。
- Codex 缓存读取属于输入子集，推理输出属于输出子集；优先采用来源总量，不能重复加总。Claude Code 的输入、输出、缓存读取和缓存写入是四类相加。改动解析器时，分别验证这两套口径。
- 同一请求、重复扫描、文件替换/截断、遥测重复批次不能增加用量。当前报表在同一提供方同一 UTC 日存在本地记录时优先本地记录；这可能低估部分覆盖日，修改规则时需先更新设计和测试。
- 来源归属必须显式绑定；普通用户的查询范围由主进程登录态约束。每个 IPC 在主进程验证发送方、权限和参数；预加载脚本只暴露命名方法，不能暴露通用 IPC、文件系统或 SQL。
- 只保存用量字段和必要的来源元数据。禁止提交真实会话 JSONL、提示词、回复、源码、数据库、凭证和遥测密钥；测试使用人工构造的无正文样本，临时数据目录在测试后清理。
- 遥测接收器只监听本机地址并验证随机密钥。只读检查已有 Codex/Claude 配置，不自动覆盖既有或组织管理设置。CSV 文本字段必须防公式注入。
- `REQ-014` 当前有 `DEV-019` / `TC-029` 待处理：CSV 表头 8 列、数据行 9 列。修改导出逻辑时同时核对列名、列数和数值语义。
- 本机开发版 DMG 未签名；公开分发的签名、公证和目标设备验收独立于本机打包通过。

## 常用命令

环境：macOS、Node.js 24、npm。先运行 `npm ci`；日常开发用 `npm start`。

| 目的 | 命令 |
| --- | --- |
| 类型检查 | `npm run typecheck` |
| 单元测试 | `npm test` |
| Electron 端到端 | `npm run test:e2e` |
| 打包目录 | `CSC_IDENTITY_AUTO_DISCOVERY=false npm run pack:dir` |
| 打包应用端到端 | `npm run test:e2e:packaged` |
| 本机未签名 DMG | `npm run pack:dmg` |

按变更范围选择必要的测试。权限、采集、统计口径和备份变更至少运行对应单元测试；跨进程或界面主流程变更运行 Electron 端到端测试。发布验证另记录 DMG、系统架构、签名/公证状态和目标设备结果。

## 完成一次变更

1. 更新工作簿中的关系和状态，确保编号唯一，需求有任务和用例，任务和用例能回溯需求。
2. 在测试用例证据栏写明实际运行的测试文件或命令、日期和结果；未运行则保持“待验证”。
3. 如果验收结论发生变化，在 `docs/validation.md` 追加有日期的记录，保留 2026-10-02 的原始验收事实。
4. 交付说明列出相关 `REQ`、`DEV`、`TC`、验证结果及仍未覆盖的边界。

## 文档分支与合并

本仓库当前远端默认分支为 `origin/main`。文档新增、更新和删除使用独立分支，命名为 `codex/docs/YYYYMMDD-主题`。从最新远端默认分支开始；若工作区已有本次文档改动，先保留并在文档分支提交。

提交前执行文档检查：`git diff --check`；核对所有新增或修改的相对链接；检查工作簿能打开、编号唯一、三方关联完整、状态与证据一致。改动工作簿时复核受影响页的显示和数据，确认没有遗留预览或临时检查文件。只有文档变更时不以应用测试替代这些检查。

检查通过后提交文档分支，推送分支，再合并并推送到 `origin/main`，最后核对远端提交。若远端默认分支、保护规则或合并权限发生变化，以仓库实际配置为准并记录未完成的步骤。
