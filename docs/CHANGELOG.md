# Token 项目变更日志

本日志按日期记录项目变更的尝试、阻塞、处理和结果。每次功能、测试、文档或发布变更完成时追加一条；同日可有多条，旧记录不覆盖。每条记录应注明变更范围、关联 `REQ/DEV/TC`、提交或证据。未解决事项保持“待处理”，不能写成已通过。SOP 文件的维护权仍属于 SOP 会话；本日志只记录可核实的结果，不替代 SOP 正文、追溯工作簿或测试证据。

## 2026-10-02

### M6 产品范围、固定超管与逐编号验收规划（文档；待实施）

- **尝试**：依据已确认的项目/模型分析、导航、更新、设置、采集诊断、反馈和管理需求，新增 REQ-031–039、DEV-034–046、TC-050–072，建立工作簿三方关联及设计、开发、测试计划。
- **卡点**：现有角色只有库内 `admin/viewer`，新固定 `admin` 超管需要兼容旧库；会话工作目录含敏感完整路径；新 23 条用例尚无代码和运行器入口，模拟文件权限也不能证明目标 Mac 授权流程。
- **处理**：约定仅用户名 `admin` 且库角色 `admin` 派生 `superadmin`，旧管理员维持原权、冲突不静默升权；完整项目路径只留本机且不进入聚合/反馈/诊断外发；所有新 TC 标待注册/待验证，并逐条指定独立临时数据库，TC-072 单列真实 Mac 人工验收。将覆盖总览、预算、别名合并、诊断包、反馈闭环、完整审计和更新回滚列为未编号候选。
- **结果**：M6 文档与追溯方案可供开发接续；工作簿新增 9 项需求、13 项任务、23 条用例及 23 条矩阵关联，旧单元格未改变。`git diff --check`、本地文档链接检查与工作簿编号/双向关联检查通过；`npm run test:cases:check` 仍核对已有 49 个入口。本批未改代码或 SOP，新功能和新用例仍待实现、待验证。

### 0.2.0 版本与安装包核对（代码 `96e99be`；文档）

- **尝试**：将应用版本升至 0.2.0，重建 `Token-0.2.0.dmg`，核对新版本识别、打包应用主流程及跨版本受信登录。
- **卡点**：先前新包仍标 0.1.0，旧版客户端无法将它识别为更高版本；0.1.0 的历史 DMG 证据也不能代替新包验证。

- **结果**：提交 `96e99be` 上重新执行 TC-029–049，21/21 退出码 0；开发会话报告门禁、打包版 7/7 Electron 和 0.2.0 DMG 结构检查通过。真实新版本安装替换、签名公证、对外发布及另一台 Mac 安装仍未人工验收。

### 服务地址口径修正（文档；待实施）

- **尝试**：复核 REQ-021、TC-032、TC-047 中的独立服务网络地址要求。
- **卡点**：上一版把 `127.0.0.1` 错写成服务只能监听的硬限制，与可配置服务器地址的目标不符。
- **处理**：将服务监听地址和 App 连接地址都定义为可配置、默认 `127.0.0.1`；验收覆盖默认、非回环配置、地址不匹配和鉴权/受保护传输。
- **结果**：设计、计划和追溯验收口径已修正；服务和相应用例仍待实现、待验证。

### M5 功能规划与追溯（文档；待实施）

- **尝试**：梳理信任设备、本地独立更新服务、每 10 分钟扫描后聚合上报、1024 进位显示和分析界面，并纳入趋势图自适应及周/月日期修复；新增 REQ-019–030、DEV-020–033、TC-030–049，更新设计、开发计划及逐项验收。
- **卡点**：当前应用没有上述服务或持久信任机制，扫描间隔仍约 30 秒；新 TC 尚无运行器注册和断言。未签名 macOS 包无法按已签名自动更新路径静默替换。
- **处理**：把新条目统一标为待实现/待验证；命令注明待注册；更新流程限定为下载并打开安装包，由用户安装。信任凭证无固定过期时间，手动退出、停用账户或重置密码撤销。
- **结果**：形成可审查的 M5 需求、任务和用例计划。代码、服务和新用例均尚未完成，不能作为功能验收证据。
